PARTE 1

História do Android

De uma startup de câmeras digitais ao sistema operacional mais usado do planeta

Origem: uma startup de câmeras digitais

Com a grande popularidade das câmeras digitais, em 2003 um grupo de desenvolvedores fundou a Android Inc., que pretendia criar um sistema operacional para câmeras.

Fundadores: Andy Rubin, Rich Miner, Nick Sears e Chris White. A empresa usou a biblioteca Bionic (C) e o kernel Linux como base do sistema.

Antes do Android: mercado fragmentado

Em 2004, observando o crescimento dos celulares, a Android Inc. mudou o foco para concorrer com os sistemas já existentes:

  • ▸Symbian — dominante em aparelhos Nokia, mas fechado e difícil de desenvolver.
  • ▸BlackBerry OS — focado em e-mail corporativo e teclado físico.
  • ▸Windows Mobile (antigo Pocket PC) — presente, porém com interface pouco amigável.

Nascimento do Android

2003

Android Inc. é fundada (Andy Rubin e equipe), inicialmente pensando em câmeras digitais.

2005

Google compra a Android Inc., ainda sem anunciar publicamente os planos.

2007

Google anuncia a plataforma e forma a Open Handset Alliance — dezenas de fabricantes e operadoras.

2008

Primeiro celular comercial: T-Mobile G1 (HTC Dream), com Android 1.0.

A ideia central: um sistema operacional open source, baseado em Linux, que qualquer fabricante poderia adotar sem pagar licença — o oposto do modelo fechado da Apple.

Aquisição pelo Google (2005)

Em 2005 a Android Inc. foi adquirida pelo Google, que manteve quase todos os desenvolvedores em um projeto ambicioso: lançar o Android como uma plataforma aberta e gratuita para dispositivos móveis, flexível o bastante para rodar em qualquer hardware.

O ceticismo da concorrência

"Mercado de celulares jamais dará certo." — Steve Ballmer, 2006
"Esses são mercados do tipo 'o vencedor leva tudo'. Meu maior erro foi ter me engajado em algum tipo de ingerência que levou a Microsoft a não ser o que o Android é. O Android é a plataforma não-Apple padrão. Era uma coisa natural para a Microsoft ocupar esse espaço." — Bill Gates, 2019

2008 — o primeiro celular Android

Em 2008 foi lançado o T-Mobile G1 (HTC Dream), com design peculiar para os padrões atuais e teclado físico deslizante.

Um grande trunfo da plataforma foi o Android Market — o início do que hoje é a Play Store.

Distribuição de apps: o Android Market

A Apple, que havia lançado o iPhone no final de 2007, não fornecia uma loja de aplicativos — apenas um site para baixar apps da própria Apple.

O Android Market tinha número limitado de aplicações no início, mas ampliou muito as possibilidades de uso do celular.

O Android hoje

É o sistema operacional móvel mais usado do mundo, presente em smartphones, tablets, TVs (Android TV), carros (Android Auto) e wearables (Wear OS).

Por isso estudamos Android: é a maior base instalada de dispositivos móveis do planeta — a plataforma com mais oportunidade para quem desenvolve aplicativos.
PARTE 2

Arquitetura do Android

As camadas que transformam um kernel Linux em uma plataforma de apps

Android em camadas

System Apps & Apps de terceiros

Telefone, Contatos, Câmera... e o app que você vai desenvolver.

Java API Framework

Activity Manager, View System, Content Providers, Notification Manager — o que você usa direto no código.

Android Runtime (ART) + Bibliotecas Nativas C/C++

ART executa o app; bibliotecas nativas cuidam de SQLite, OpenGL, WebKit, etc.

Hardware Abstraction Layer (HAL)

Traduz chamadas do framework para os drivers reais de câmera, sensores, bluetooth...

Kernel Linux

Drivers, gerenciamento de memória e processos, segurança, energia.

Como desenvolvedor, você programa quase sempre na camada Java API Framework — as camadas de baixo já vêm prontas no sistema.

Arquitetura — Kernel Linux

Estabilidade e segurança: o Android é baseado no robusto kernel Linux.

Compatibilidade de hardware: o amplo suporte do Linux a diferentes configurações facilita a adoção por uma ampla gama de fabricantes.

Arquitetura — Abstração de Hardware (HAL)

A HAL é a camada que permite ao Android se comunicar com o hardware (câmera, GPS, sensores, Wi-Fi...) de forma padronizada, independente do fabricante.

  • ▸O Android não precisa saber os detalhes de cada hardware.
  • ▸Fabricantes apenas implementam as interfaces HAL.
  • ▸O mesmo Android funciona em dispositivos diferentes.

Por que isso importa na prática?

  • ▸Portabilidade: o mesmo APK roda em aparelhos de fabricantes diferentes porque todos implementam o mesmo HAL sobre hardwares distintos.
  • ▸Sandbox de segurança: cada app roda em sua própria instância da ART com permissões isoladas — um app não acessa dados de outro sem permissão.
  • ▸Reuso via Framework: classes como Activity, View e Intent escondem toda a complexidade das camadas de baixo.
Fixando o conceito: quando você chama startActivity(), o pedido atravessa o Framework, passa pela ART, pode acionar o HAL (ex.: abrir a câmera) e, no fim, o Kernel Linux gerencia o processo de verdade.

PARTE 3

Criando um Projeto Android

Linguagem, interface e a estrutura de pastas do Android Studio

Android Studio

É a IDE oficial para desenvolvimento Android, mantida pelo Google e baseada no IntelliJ IDEA.

  • ▸Gerencia o projeto com Gradle (build, dependências, variantes de build).
  • ▸Inclui emulador (AVD — Android Virtual Device) para testar sem um celular físico.
  • ▸Suporta as duas linguagens oficiais — Java e Kotlin — e as duas formas de interface — XML (Views) e Jetpack Compose.
No assistente "New Project": você escolhe um template (ex.: Empty Views Activity ou Empty Activity/Compose), o nome do pacote, a linguagem e a versão mínima do Android suportada.

Android Studio: edição, emulação e depuração

O Android Studio fornece gestão de bibliotecas, ferramenta de emulação, design de interface e depuração — tudo em um só lugar.

Android SDK e o SDK Manager

O Android SDK é o conjunto de ferramentas do Google para criar apps: compilador, emulador e documentação. O Android Studio é a IDE que reúne tudo isso.

O SDK Manager gerencia as bibliotecas e recursos do SDK, incluindo as diferentes versões da API disponíveis para desenvolvimento e teste.

API Level: cada versão, um número

A API do Android é organizada em níveis que correspondem aos recursos disponíveis no sistema — do Ice Cream Sandwich (API 15) ao Android 10 (API 29) e além.

Linguagem: Java × Kotlin

☕ Java

  • Linguagem original do Android desde 2008
  • Mais verbosa: getters/setters, classes anônimas
  • Sem null-safety no tipo — NullPointerException é comum
  • Maior volume de tutoriais e código legado

🎯 Kotlin

  • Linguagem oficialmente preferida pelo Google desde 2019
  • Mais concisa: data class, inferência de tipo, lambdas
  • Null-safety no próprio tipo (String?)
  • 100% interoperável com Java na mesma JVM

Nesta disciplina começamos com Java para fixar os fundamentos (ciclo de vida, listeners, XML) — Kotlin fica como evolução natural depois.

Interface: XML × Jetpack Compose

📄 XML (View System)

  • Layout descrito em arquivo .xml, separado do código
  • Componentes acessados via findViewById()
  • Atualização de tela é manual (setText(), etc.)
  • Modelo usado pela imensa maioria dos apps em produção hoje

🧩 Jetpack Compose

  • Interface descrita em funções @Composable, em Kotlin
  • Sem XML — a tela é código
  • Recomposição automática quando o estado muda
  • Abordagem moderna, recomendada pelo Google para projetos novos
Escolha da disciplina: começamos com XML porque expõe melhor a estrutura de um projeto Android e o ciclo de vida da Activity — a base que também sustenta o Compose.

Onde o Android nativo se encaixa

Nativo, Híbrido/Cross-platform ou PWA — clique em cada categoria para ver as camadas do dispositivo.

Como o código vira pixel na tela?

Clique em um framework e acompanhe o fluxo de renderização, camada por camada.

Da tela padrão do Android Studio a um app que reage ao toque

Criando o projeto

  3. 3Aguardar o Gradle sincronizar as dependências do projeto.
  4. 4Rodar (▶) em um emulador (AVD) ou em um celular físico com modo desenvolvedor ativo.
O próprio assistente já gera um projeto funcional: uma Activity, um layout XML e o texto "Hello World!" na tela.

Hello World — o que já vem pronto

Trecho do arquivo res/layout/activity_main.xml:

<TextView
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Hello World!"
    app:layout_constraintBottom_toBottomOf="parent"
    app:layout_constraintTop_toTopOf="parent"
    app:layout_constraintStart_toStartOf="parent"
    app:layout_constraintEnd_toEndOf="parent" />

Trecho do arquivo MainActivity.java:

public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main); // liga a Activity ao layout XML
    }
}

Evoluindo: contador de cliques (1/2)

Passo 1 — damos um id ao TextView no XML e o associamos ao código com findViewById():

<TextView
    android:id="@+id/tvShowContador"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content" />
TextView tvShowContador;
int contador = 0;

@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_main);
    tvShowContador = findViewById(R.id.tvShowContador);
    tvShowContador.setText(String.valueOf(contador));
}

Evoluindo: contador de cliques (2/2)

Passo 2 — um OnClickListener incrementa o contador a cada toque no texto:

tvShowContador.setOnClickListener(v -> {
    contador++;                                   // incrementa
    tvShowContador.setText(String.valueOf(contador)); // atualiza a tela
});
O que isso já demonstra: a ligação XML ↔ código (findViewById) e o modelo de eventos do Android (View.OnClickListener) — a base de qualquer interação em tela.

Persistir esse valor entre rotações de tela e fechamento do app (onSaveInstanceState, SharedPreferences) é assunto da próxima aula, sobre ciclo de vida da Activity.

PARTE 5

Emulador e ADB

Testando e depurando sem (ou com) um celular de verdade

Emulador do Android Studio

O Emulador do Android Studio simula um dispositivo Android virtual no computador, permitindo testar e depurar aplicativos sem precisar de um celular físico.

Reproduz fielmente o funcionamento do Android real: tela, botões, sensores, GPS, câmera, chamadas e muito mais.

  • ▸Interface gráfica completa: simula um smartphone ou tablet real.
  • ▸Sensores virtuais: localização (GPS), acelerômetro, câmera, bateria.
  • ▸Integração com o ADB para logcat, instalação e testes.

Habilitando o Modo Desenvolvedor

  1. 1Abrir Configurações → Sobre o telefone.
  2. 2Tocar 7 vezes seguidas em "Número da versão" (ou "Build number").
  3. 3O aparelho confirma: "Agora você é um desenvolvedor!"
  4. 4Uma nova opção aparece em Configurações → Sistema → Opções do desenvolvedor.
Atenção: essas opções expõem configurações avançadas do aparelho — não é necessário mexer em nada além da depuração USB para os fins da disciplina.

Por que ADB, e não SSH?

Embora o Android seja um sistema operacional Linux, o acesso a recursos do sistema deve sempre passar pelas políticas e permissões da plataforma Android.

Por isso, para acessar remotamente o dispositivo não usamos SSH, e sim uma aplicação própria: o ADB.

Arquitetura do ADB

O ADB (Android Debug Bridge) é uma ferramenta versátil de linha de comando, incluída no Android SDK, que permite a desenvolvedores e usuários comunicarem-se com um dispositivo Android a partir de um computador.

Três componentes: ADB Daemon (adbd) no aparelho, ADB Server no computador (fica escutando na porta TCP 5037) e o Client — o comando adb que você digita no terminal.

Fonte: developer.android.com/studio/command-line/adb

Depuração USB: ativando na prática

  1. 1Em Opções do desenvolvedor, ativar USB debugging.
  2. 2Conectar o celular ao computador via cabo USB.
  3. 3Autorizar a chave RSA do computador na caixa de diálogo que aparece no celular.
Essa opção permite que o computador envie comandos e instale aplicativos diretamente no aparelho via cabo USB.

Como usar o ADB

No diretório onde está instalado o SDK e as ferramentas de plataforma (~/Android/Sdk/platform-tools), execute ./adb devices para listar os dispositivos com ADB habilitado:

ComandoFunção
adb logcatExibe os logs do sistema Android em tempo real (útil para depuração)
adb shellAbre um terminal (shell) dentro do sistema Android
adb install meu_app.apkInstala o arquivo APK no dispositivo conectado
adb push arquivo.txt /sdcard/Envia o arquivo do computador para o armazenamento interno do Android
adb pull /sdcard/arquivo.txt .Copia um arquivo do Android para o computador local
adb rebootReinicia o dispositivo conectado

Atividade prática: explorando o ADB

Foco em manipulação de arquivos (push/pull/shell) — mostra a comunicação entre o PC e o emulador.

Com o emulador rodando, abra o terminal e siga os passos:

  1. Crie um arquivo de texto rápido no PC: echo "Teste ADB" > teste.txt
  2. Envie este arquivo para o emulador: adb push teste.txt /sdcard/
  3. Entre no sistema do Android: adb shell
  4. Liste os arquivos para provar que ele chegou lá: ls /sdcard/ (depois exit para sair)
  5. Traga o arquivo de volta com outro nome: adb pull /sdcard/teste.txt teste_recebido.txt

Atividade prática: monitorando com logcat

Foco em diagnóstico — observando o fluxo de logs do sistema em tempo real.

  1. Verifique se o emulador está reconhecido: adb devices
  2. Inicie o monitoramento do sistema: adb logcat
  3. Desafio: interaja com o emulador (clique em alguns apps) e observe o terminal. Pressione Ctrl+C para parar o log.
  4. Acesse o sistema de arquivos digitando adb shell e explore as pastas com ls. (exit para voltar).
