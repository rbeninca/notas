PARTE 1

História da Internet e da Web

Duas invenções diferentes, décadas de distância, o mesmo fio condutor

Antes de tudo: um contexto de guerra

A Internet não nasceu para conectar pessoas casualmente — nasceu de pesquisa militar e acadêmica, num momento de disputa geopolítica. A seguir, a linha do tempo que vai desse contexto até a Web de hoje:

A Internet é a infraestrutura de rede: surgiu nos anos 1960. A Web é um serviço que passou a rodar sobre essa infraestrutura só 30 anos depois, em 1989-91, para compartilhar documentos científicos — e virou a maior plataforma de aplicações do mundo. Três invenções de Tim Berners-Lee a sustentam até hoje: HTML, URL e HTTP.

1957–58 — Sputnik e a criação da ARPA

O lançamento do satélite soviético Sputnik (1957) acelera a preocupação dos EUA com pesquisa estratégica. Em resposta, o governo cria em 1958 a ARPA (Advanced Research Projects Agency) — uma agência do Departamento de Defesa para financiar e coordenar pesquisas avançadas.

Anos 1960 — Uma visão de rede e computadores isolados

J. C. R. Licklider defende a ideia de computadores conectados em rede — a "Galactic Network", precursora da Internet. Ao mesmo tempo, universidades e centros de pesquisa financiados pela ARPA tinham grandes computadores isolados, caros e difíceis de compartilhar.

1966–1969 — De Bob Taylor à ARPANET

Bob Taylor consegue financiamento para interligar os centros de pesquisa. Larry Roberts estrutura o projeto tecnicamente, e a empresa BBN constrói os IMPs — minicomputadores precursores dos roteadores. Em 1969, a ARPANET entra em operação: o 1º nó foi na UCLA, a 1ª mensagem tentou enviar LOGIN ao Stanford Research Institute — só chegaram as letras LO.

1970s–1985 — TCP/IP e a NSFNET

A ARPANET se expande e consolida ideias como comutação de pacotes. Em 1983, a adoção do TCP/IP transforma a Internet numa rede de redes — a base técnica até hoje. Em 1985, a NSFNET amplia o acesso acadêmico para além do ambiente militar.

Março de 1989 — A proposta de Tim Berners-Lee

No CERN, o físico e engenheiro de software Tim Berners-Lee circula o documento "Information Management: A Proposal" — uma resposta ao problema de pesquisadores perderem informação por causa de sistemas incompatíveis e alta rotatividade de pessoal.

Propõe um sistema de hipertexto distribuído: documentos ligados por links, acessíveis de qualquer computador da rede, sem uma estrutura hierárquica fixa.

Seu supervisor, Mike Sendall, anota na proposta: "Vague, but exciting" ("vago, mas empolgante") — e autoriza o projeto.

1990 — As três invenções e o primeiro navegador

Ao longo de 1990, Berners-Lee implementa os três pilares que ainda sustentam a Web: HTML (a linguagem dos documentos), URL (o endereçamento) e HTTP (o protocolo de transferência).

Cria também o WorldWideWeb — ao mesmo tempo navegador e editor de páginas — rodando em um computador NeXT, que também serve como o primeiro servidor Web do mundo.

Agosto de 1991 — A primeira página publicada

Berners-Lee publica a primeira página Web pública, explicando o próprio projeto: o que é a World Wide Web, como instalar um servidor e como criar hiperlinks. Endereço original: info.cern.ch.

É também o convite formal: ele anuncia o projeto em fóruns de discussão da época (Usenet), convidando outros pesquisadores a experimentar e contribuir.

1989 → proposta escrita
1990 → HTML + URL + HTTP + navegador + servidor
1991 → primeira página publicada, ao alcance de todos

1993–1994 — Mosaic e a fundação do W3C

O navegador Mosaic (1993) populariza a Web ao integrar imagens ao texto, tornando-a visual e acessível. Em 1994, Berners-Lee funda o W3C (World Wide Web Consortium) para coordenar padrões abertos e evitar a fragmentação entre navegadores e tecnologias incompatíveis.

1995–2001 — Interatividade: JavaScript e CSS

Surge o JavaScript (1995) para tornar páginas interativas — a Web deixa de ser só documento estático. O W3C publica o CSS1 (1996) e CSS2 (1998) para separar apresentação de conteúdo; a partir de 1999-2001 o CSS passa a evoluir em módulos (o que hoje chamamos, informalmente, de "CSS3").

Anos 2000 até hoje — Web 2.0 e plataforma universal

Usuários passam a produzir conteúdo em escala (blogs, redes sociais, wikis) — a Web 2.0. De 2010 em diante, aplicações complexas rodam direto no navegador, e hoje a Web é uma plataforma universal: mobile, APIs, nuvem, bancos distribuídos, tempo real.

PARTE 2

Internet × Web

Agora que vimos a história de cada uma, vamos separar claramente os conceitos

Duas camadas diferentes

Confundir os dois é comum — mas, como vimos na história, são coisas separadas por décadas e camadas diferentes:

🌐 Internet

A infraestrutura. Rede física e lógica global de computadores interligados, nascida na Guerra Fria.

Transporta vários serviços: e-mail, FTP, streaming, jogos, VoIP... e também a Web.

Protocolos base: TCP/IP.

🕸️ Web (WWW)

Um serviço que roda sobre a Internet, criado 20 anos depois dela, no CERN.

Sistema de documentos e aplicações interligados por hiperlinks, acessados via HTTP no navegador.

Protocolo: HTTP/HTTPS.

Analogia: a Internet é o sistema de estradas; a Web é um dos serviços que trafega por elas (como uma transportadora). E-mail é outro serviço diferente, na mesma estrada.
PARTE 3

W3C

Quem garante que a Web funcione igual em qualquer navegador

O que é o W3C?

O World Wide Web Consortium foi fundado por Tim Berners-Lee em 1994, logo depois de o Mosaic popularizar a Web, para resolver um problema concreto:

  • ▸Sem um padrão comum, cada navegador poderia interpretar HTML e CSS de um jeito diferente.
  • ▸O W3C publica recomendações (specs) abertas: HTML, CSS, acessibilidade, internacionalização, APIs da Web...
  • ▸Não é uma lei — é um consenso técnico que navegadores, empresas e desenvolvedores adotam voluntariamente.
É por causa do W3C que uma tag <p> se comporta de forma parecida no Chrome, no Firefox e no Safari — sem consenso, a Web teria fragmentado como aconteceu nos primeiros anos dos navegadores (a "guerra dos navegadores" dos anos 1990).

Referência de tags: developer.mozilla.org / w3.org

Você não precisa decorar todas as tags HTML — precisa saber onde consultar:

w3.org  ·  developer.mozilla.org (MDN)
  • ▸Documentação oficial de todas as tags HTML, com sintaxe, atributos e exemplos.
  • ▸Referência de propriedades CSS e APIs JavaScript do navegador.
  • ▸Mostra a compatibilidade entre navegadores — essencial antes de usar um recurso novo em produção.
Vamos abrir o site juntos em aula. Acostume-se a consultá-lo: é a fonte confiável, à frente de tutoriais aleatórios ou respostas desatualizadas.
PARTE 4

Da Página Estática ao Back-end Moderno

PHP, JavaScript no servidor e o ecossistema de hoje

O problema: páginas sempre iguais

A Web de 1991-94 servia apenas arquivos HTML prontos, gravados no disco do servidor. Toda vez que alguém visitava, recebia exatamente o mesmo conteúdo — não dava para mostrar um carrinho de compras, um resultado de busca ou um post de outro usuário.

Faltava um jeito de o servidor gerar HTML na hora, com base em dados — é aqui que entram as linguagens de back-end.

A trilha das linguagens de back-end

1995

PHP

Criado para gerar páginas dinamicamente. Populariza o modelo "script embutido no HTML" e domina a web dinâmica por anos (WordPress, Facebook original).

1995

JavaScript

Nasce só para rodar no navegador. Por 14 anos, ficou restrito ao lado cliente.

2009

Node.js

Leva o motor V8 (do Chrome) para fora do navegador. Pela primeira vez, JavaScript roda também no servidor.

Hoje

Ecossistema atual

Uma única linguagem (JS/TypeScript) do front ao back. Frameworks como Express, Next.js; PHP continua vivo (Laravel); Python (Django), entre outros.

Por que o Node.js foi um marco?

  • ▸Antes: front-end em JavaScript, back-end em outra linguagem (PHP, Java, .NET...) — dois contextos, duas sintaxes.
  • ▸Com Node.js: o mesmo desenvolvedor pode usar JavaScript nos dois lados, compartilhando código e conhecimento.
  • ▸Abriu caminho para o ecossistema npm — hoje o maior repositório de pacotes de código do mundo.
Nesta disciplina você vai ver ambos os lados: HTML/CSS/JS no navegador primeiro, e mais adiante como esse conteúdo pode ser gerado dinamicamente no servidor.

Domínio e DNS

Computadores se encontram por endereços IP (ex.: 142.250.79.110), mas pessoas decoram nomes. O DNS (Domain Name System) é a "agenda telefônica" da Internet que traduz nome → IP.

💻Navegadorquer exemplo.com.br
1. Qual o IP?
2. É 142.250.79.110
📒Servidor DNSa "agenda" da Web
  • Hierarquia do domínio www.exemplo.com.br: br (TLD de país) → com → exemplo → www (subdomínio).
  • O resultado da consulta fica em cache (no SO e no navegador) para acelerar acessos futuros.

Navegador e Servidor Web

🖥️ Navegador (cliente)

Monta a requisição HTTP e a envia.

Recebe HTML, CSS e JS e os renderiza na tela.

Executa JavaScript, gerencia cookies, cache e segurança.

Ex.: Chrome, Firefox, Edge, Safari.

🗄️ Servidor Web

Fica "escutando" requisições em uma porta.

Serve arquivos estáticos ou aciona uma aplicação que gera a resposta.

Devolve a resposta HTTP com status, cabeçalhos e corpo.

Ex.: Apache, Nginx, IIS, Node.js.

Estático = arquivo pronto no disco. Dinâmico = conteúdo gerado na hora (PHP, Node.js, consulta a banco) — é aqui que entra a programação para internet.

HTTP e HTTPS

HTTP (HyperText Transfer Protocol) é o conjunto de regras que define como cliente e servidor trocam mensagens na Web.

HTTP

Texto trafega em claro — pode ser lido/alterado por terceiros.

Porta padrão 80.

HTTPS 🔒

HTTP sobre TLS/SSL: tudo é criptografado.

Garante sigilo, integridade e autenticidade (certificado).

Porta padrão 443. Hoje é o padrão da Web.

Uma mensagem HTTP sempre tem: linha inicial (método/URL ou status) + cabeçalhos (metadados) + corpo opcional (dados).

Métodos (Verbos) HTTP

O método diz qual ação o cliente quer realizar sobre o recurso:

MétodoAçãoExemplo de usoAltera dados?
GETLer / buscarAbrir uma página, listar produtosNão
POSTCriar / enviarEnviar formulário, cadastrar usuárioSim
PUTSubstituirAtualizar um registro inteiroSim
PATCHAtualizar parcialMudar só o e-mail do usuárioSim
DELETERemoverApagar um produtoSim
Convenção REST: cada verbo mapeia uma operação CRUD (Create=POST, Read=GET, Update=PUT/PATCH, Delete=DELETE). GET nunca deve alterar o servidor.

Códigos de Status HTTP

Toda resposta traz um número de 3 dígitos. O primeiro dígito indica a categoria:

1xxInformativo — requisição recebida, processo continua (raro no dia a dia).
2xxSucesso — 200 OK, 201 Created, 204 No Content.
3xxRedirecionamento — 301 Moved Permanently, 302 Found.
4xxErro do cliente — 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found.
5xxErro do servidor — 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable.
Dica de memorização: 4xx a culpa é de quem pediu; 5xx a culpa é de quem respondeu.

Recapitulando

  • ▸A Internet nasceu na Guerra Fria (ARPANET, 1969); a Web nasceu 20 anos depois, no CERN (1989-91) — são camadas diferentes.
  • ▸O W3C mantém os padrões abertos que fazem HTML, CSS e APIs da Web funcionarem igual em qualquer navegador.
  • ▸De páginas estáticas evoluímos para back-end dinâmico: PHP (1995) e, depois, JavaScript no servidor com Node.js (2009).
  • ▸A Web funciona no modelo cliente-servidor: URL → DNS → requisição HTTP → processamento → resposta → renderização.
  • ▸Métodos dizem a ação (GET, POST, PUT, DELETE); status dizem o resultado (2xx ok, 4xx cliente, 5xx servidor).
