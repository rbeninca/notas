Questão 1 — Formulários HTML e envio de dados

Um estudante criou o formulário abaixo. Considere que o usuário mantém os valores exibidos e clica em Enviar. O navegador está com a validação HTML padrão ativada. 

<form action="/contato" method="get">
  <label for="email">E-mail</label>
  <input id="email" name="email" type="email"
         value="ana@exemplo.com" required>

  <label for="curso">Curso</label>
  <select id="curso">
    <option value="ads" selected>ADS</option>
    <option value="redes">Redes</option>
  </select>

  <label><input type="checkbox" name="avisos"
                value="sim" checked> Receber avisos</label>
  <button type="submit">Enviar</button>
</form>

Item a [0,8] — método e dados enviados

Resposta: o método HTTP é GET. Os pares enviados são email=ana@exemplo.com e avisos=sim.

Como determinar: o atributo method="get" define o método. Para enviar um controle, o navegador precisa de um name e de um valor válido. O campo de e-mail tem name="email"; a caixa marcada tem name="avisos" e value="sim". Por isso, os dados aparecem na query string como /contato?email=ana@exemplo.com&avisos=sim.

O select não tem atributo name, então sua seleção não é enviada. O botão também não tem name e não acrescenta um par nome=valor.

Item b [0,7] — enviar a seleção do curso

Resposta: adicione name="curso" à tag <select>. O par enviado será curso=ads.

Um controle pode mostrar uma opção selecionada sem enviá-la: o navegador serializa o valor do controle associado a um nome. A tag corrigida fica assim: 

<select id="curso" name="curso">

Como a opção selecionada tem value="ads", o par é curso=ads. Se esse nome fosse acrescentado, a query string também incluiria esse par.

Item c [0,5] — não colocar os dados na URL

Resposta: altere method="get" para method="post". Em um envio POST, os campos costumam ser transmitidos no corpo (body) da requisição, em vez de compor a query string da URL.

Essa mudança evita que os valores sejam colocados na URL como parâmetros GET; ela não criptografa os dados. Para proteger os dados durante o transporte, o site também deve usar HTTPS.

Item d [0,5] — validação do e-mail

Resposta: não. Com o valor ana@, a validação nativa bloqueia o envio.

O atributo required verifica se o campo está preenchido; ana@ não está vazio, então satisfaz essa exigência. Porém, type="email" também verifica se o valor tem formato de endereço de e-mail válido. ana@ não tem um domínio após o @, por isso falha nessa validação e o formulário não é enviado até que o valor seja corrigido.
